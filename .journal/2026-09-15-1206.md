# Journal: Built-in skill installer

- Timestamp: 2026-09-15 12:06 (Asia/Singapore)
- Core Decision/Topic: Add a `skill` subcommand so installing the agent guide no
  longer requires the external Skills CLI.
- Options Considered: Keep documenting `npx skills@latest add HuakunShen/bread`;
  copy the tui-test interactive picker; add a non-interactive subcommand with a
  global default and opt-in flags.
- Final Decision & Rationale: Add `bread skill` (print) and `bread skill --add`
  (install). The default scope is global, matching the request, and the flag
  surface (`--project`, `--target agents|claude|codex`, `--dir`) replaces the
  interactive picker so the command works in scripts and CI. A default install
  only writes into agent configuration directories that already exist, so it does
  not create `~/.claude` or `~/.codex` for users who do not run those hosts.
- Key Changes Made: `embed.go` embeds the canonical
  `skills/efficient-codebase-navigation/SKILL.md` so there is one source of
  truth for the printed guide and every installed manifest. `internal/skill`
  resolves destinations, dedupes symlinked roots, and writes `SKILL.md`.
  `cmd/bread/main.go` routes `skill` and `skill --add`. README, Chinese README,
  `docs/zh-CN.md`, the skill itself, and both installers mention the command.
  New unit and CLI tests cover paths, targets, env overrides, and exit codes.
- Future Considerations: Consider honoring `CLAUDE_CONFIG_DIR`/`CODEX_HOME`
  style variables for other hosts if their global skills directories become
  common, and decide whether the installers should run `bread skill --add`
  automatically instead of printing a hint.
