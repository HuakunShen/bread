# Journal: Windows self-upgrade helper

- Timestamp: 2026-09-15 07:14 (Asia/Singapore)
- Core Decision/Topic: Fix the Windows self-upgrade process before the production release.
- Options Considered: Keep the single `/C` command string; invoke the helper through `cmd.exe` with the command after `/C` passed as separate arguments.
- Final Decision & Rationale: Use separate arguments. The real rog16-windows test showed that passing the whole command as one argument caused Go `os/exec` to quote it for `CreateProcess`, after which `cmd.exe` treated the surrounding quotes as literal text. The helper returned success without replacing the binary and left temporary directories behind.
- Key Changes Made: `internal/update/update.go` now invokes `cmd.exe /D /C call <script> & if not errorlevel 1 rmdir /S /Q <temp>` through separate `exec.Command` arguments; local Go tests pass.
- Future Considerations: Re-run the real Windows upgrade test after publishing the patch release, then enable the optional Homebrew automation only after a narrowly scoped tap token is configured.
